# P2: The POSIX language (0.1.x)

**Status:** in progress (0.1.0, 0.1.1 done).

## Goal

The whole POSIX shell language (XCU chapter 2) and its utilities that
must be builtins, done well enough that tam-clam passes a spec suite run
against dash, bash --posix, mksh and busybox ash, and survives fuzzing.

## Versions

- **0.1.0** Command substitution (`$(...)` and backquotes, parsed at parse
  time as a subtree, not re-lexed at run time), `$'...'` strings (in
  POSIX since 2024), arithmetic expansion with
  64-bit signed integers and checked overflow, field splitting by `IFS`,
  and pathname expansion. Our own pattern matcher, used by globbing,
  `case` and the `${x%pat}` forms; it runs in linear time, never
  backtracking exponentially.
- **0.1.1** `&` and `wait`, `$!`. `trap` for signals and `EXIT`, run at
  safe points only. The special builtins: `set`, `shift`, `eval`, `.`,
  `export`, `readonly`, `unset`, `exec`, `return`, `break`, `continue`,
  `times`, `:`.
- **0.1.2** The regular builtins: `read`, `printf`, `echo` (POSIX-style:
  no options except as dash does), `test` and `[`, `getopts`, `command`,
  `type`, `hash`, `umask`, `alias` and `unalias`, `kill`, `pwd`, `ulimit`,
  `false`, `true`.
- **0.1.3** `set -e` (exactly as POSIX words it, including its quirks),
  `set -u`, `set -o pipefail` (now in POSIX 2024), `set -x` with `PS4`
  and line numbers, `set -f`, `set -C`, `set -n` (parse only, which also
  gives us a syntax checker).
- **0.1.4** The spec suite and fuzzing (below). Bugs found become
  regression tests.
- **0.1.5** Lint mode (below).

## Lint mode

`tam-clam --lint FILE...` parses each file with the same parser that runs
it, runs nothing, and prints one warning per risky construct with its file,
line and column, in the style of shellcheck. The status is 0 when there
are no warnings, 1 when there are, and 2 on a syntax error. First checks:

- an unquoted expansion inside `[ ]` or `test`, or as a `case` word;
- `cd` in a script whose failure is not checked;
- `$*` where `"$@"` was almost certainly meant;
- `for f in $(ls ...)` and other splitting of command output;
- a variable that is used but never set in the file.

Each check has a short name, so a line can silence one check with a
comment (`# lint: allow unquoted-test`), and each has a spec test.
Lint is built on the column-precise locations that the error messages
need anyway.

## Spec suite

Taken as an idea from Oils (`spec/*.test.sh`) and mksh (`check.t`): one
file per topic in `tests/spec/`, each case with its script and expected
output, plus notes where other shells differ:

    #### cd with no arguments goes home
    HOME=/tmp; cd; pwd
    ## stdout: /tmp

    ## BUG mksh stdout: ...

A runner runs every case under tam-clam and every installed reference
shell, and prints a table. Where the reference shells disagree, the case
records which behaviour tam-clam follows and why.

## Fuzzing

- A `tests/fuzz/` target feeds bytes to the lexer and parser, and one to
  the expander, built with clang's libFuzzer when clang is installed (a
  build-time tool only; nothing is linked into the shell).
- Without clang, a plain C driver replays the corpus, so corpus files
  stay regression tests.
- Acceptance: a 24-hour run with no crash, hang, leak or sanitizer
  report.

## Acceptance

- Every spec case passes, or is a recorded, deliberate difference.
- `make sanitize` and the fuzz replay pass.
- Real scripts run: the Arch `makepkg` helpers that use only POSIX sh,
  `configure` scripts generated by autoconf, and the Tamlinux shell
  scripts.

## Dependencies

- None added. Pattern matching, arithmetic and `printf` are our own code.

## Risks

- **`set -e` is subtle.** POSIX's rules for when errexit is ignored are
  easy to get wrong. Oils' `spec/errexit.test.sh` cases are the guide.
- **Performance of `$(...)`.** Every substitution forks. A no-fork path
  for builtins is in P4 as an idea, after correctness.
